# UI/UX audit and improvement pass — 19 October 2026

Scope: main menu, Online setup, shared multiplayer room, character/weapon selection, settings, history, match menu and HUD. Baseline: main after PR #173. Android remains the shipping target; Apple HIG informs readability and interaction rather than making this Godot canvas a native Apple interface.

## Design rules applied

Use two existing typefaces: Bungee for short game headings/actions and Source Sans 3 Medium for reading. This preserves the owner's current font direction. HIG permits custom typefaces; copying SF Pro into the Android/web bundle is unnecessary.

The shared 720 px design scale is calibrated against a 360 pt phone: body 34 px (17 pt), detail/compact action 28 px (14 pt), primary action 32 px (16 pt), caption 24 px (12 pt), heading 40 px (20 pt). Primary reading content uses body; compact metadata uses detail/caption. Screen margins are 32 px, panel padding 24 px, component gaps 16 px and section gaps 24 px. New or revised menu controls have at least 88 px touch height (44 pt at the reference width). Gameplay weapon buttons retain their larger thumb targets.

Amber identifies the primary action or selected option. Secondary actions use slate; blue is reserved for navigation and existing game context; green communicates confirmation/success; red identifies destructive actions or errors. Text accompanies readiness, team identity and errors. Selected cards have a thicker frame in addition to color. Game-world team indicators are not recolored by this pass.

Do not fill unused space with instructions or repeat the screen title in the action. Show errors near the relevant field, keep one clear next action, let reading content wrap/scroll, and keep essential room/loadout confirmation actions outside the content scroll.

## Findings and changes

| Priority | Finding | Applied improvement |
|---|---|---|
| P0 | Online and Hotspot render different rooms and expose different character/host controls | Both use the same room view and server-confirmed map, format, teams and character state. Only Online shows the eight-character code and Copy action. Hotspot discovery remains code-free. |
| P0 | Create/Join can arrive before the server receives the selected name | Wait for WELCOME before sending the pending room action; assert names on the authoritative room. Deferred Hotspot callbacks retain their original transport and discovery stops on scene exit. |
| P0 | Untimed Practice setup has no navigation out | Back leaves Practice directly. Multiplayer Back requests confirmation; the server pick deadline continues and closes a stale dialog on timeout. Swap Back closes selection. |
| P1 | Secondary reading text is 17–22 design pixels in the weapon guide/history | Larger body/detail styles, wrapping descriptions, stacked history metadata and less repeated heading text. |
| P1 | White action labels on saturated green/blue/red have inconsistent contrast | Darker semantic action fills; automated checks cover normal, hover and pressed text at 4.5:1 or better. |
| P1 | Match clock/format and tagged-player labels are too small; gear/swap targets are small | Larger scoreboard and metadata, readable tagged-card text, and 88 px gear/swap targets. |
| P1 | Host options occupy guest attention as disabled buttons | Guests see a concise current-format summary; hosts retain editable controls. |
| P1 | Room code validation appears far from the field | Inline format error and focus on the code field. Editing clears the stale message. |
| P1 | Settings slider is squeezed between label and percentage | Full-width slider below its label/value row; shared sound/vibration controls in the match menu. |
| P1 | Match menu styling and exits differ from the rest of the app | Shared dialog typography, spacing and scroll bounds; one reusable leave confirmation that explains local-host consequences. Infrequent Practice tools start collapsed; persistent menu controls keep their signal wiring. |
| P2 | Empty statuses reserve rows; copy repeats instructions and labels | Empty status rows collapse. Concise loadout title/Ready labels, character labels, history empty state and explicit Cancel Ready action. |
| P2 | Long modal content can extend beyond the screen | Safe-area margins and a bounded scroll container; short dialogs remain compact and centered. |

## Regression and visual checks

Automated checks cover semantic contrast in active interaction states, tall-dialog viewport bounds, repeated menu entry without losing wired controls, confirmation behavior, multiplayer timeout during a leave dialog, Online-only room codes, guest summaries, server-confirmed format/character updates, room leave, and reconnect behavior. The full existing deterministic simulation/network suite remains mandatory.

Visual checks use the exported single-threaded web build at 720×1280, 390×844 and 360×640. Check main actions, settings, rename, weapon guide, Online create/join, room code, team slots, 3v3 scrolling, character selection, loadout, and match menu/HUD. Hardware checks below are still required.

## Remaining work, in order

1. Player-controlled text-size scaling and largest-size reflow are delivered in the [accessibility follow-up](2026-10-19-accessibility.md). OS Dynamic Type/Bold Text is not automatically inherited by this custom canvas. Do not market the current UI as fully HIG-compliant.
2. Audit native Android TalkBack roles, accessible names, focus order, gamepad/keyboard navigation and switch access. Tooltips/text labels are not proof of screen-reader integration.
3. Test Android cutouts, display/font scaling, physical multitouch, virtual-keyboard occlusion, Back navigation and clipboard permissions on real devices. Browser validation cannot replace this.
4. Reduced decorative motion is delivered in the accessibility follow-up; competitive telegraph timing is retained. Increased-contrast preferences and remaining gameplay/camera comfort options need a separate pass.
5. Profile populated 3v3 rooms and gameplay on the minimum/recommended Android hardware. Verify HUD occlusion and text at actual viewing distance, outdoors and in low light.
6. Resolve the existing Toni/Popoy/Inday torn-mesh findings with owner-supplied assets; assess world/HUD contrast again after the final art is present.

## Reference guidance

Apple HIG pages reviewed for this pass:

- [Typography](https://developer.apple.com/design/human-interface-guidelines/typography): readable sizes, limited typefaces, hierarchy and custom-font accessibility.
- [Layout](https://developer.apple.com/design/human-interface-guidelines/layout): alignment, safe areas, adaptable content and touch targets.
- [Color](https://developer.apple.com/design/human-interface-guidelines/color): consistent semantic roles and sufficient contrast.
- [Writing](https://developer.apple.com/design/human-interface-guidelines/writing): clear verbs, fewer words, consistent terms and actionable errors close to the problem.

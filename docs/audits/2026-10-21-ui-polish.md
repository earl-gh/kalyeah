# UI polish (P4 of the lead review)

Findings from [the review](2026-10-21-lead-review.md), section 3.2, and what happened to each.

| # | Finding | Result |
| --- | --- | --- |
| U2 | Team identity was colour only | **Done.** A circle (ally) or diamond (enemy) on every other kid's health bar, plus a *Colour-blind colours* switch in Settings (blue and orange, a pale yellow bar for you instead of green). `TeamColors` is the one place the HUD asks for team colours. |
| U3 | The console was 23% of the screen and mostly empty | **Done in part.** Your health (number and bar) sits in the middle of the shell where no thumb is. The painted shell is still an owner asset (2D image). |
| U4 | Home bar / notch under the console | **Done in code, not checked on a device.** The console grows by the system's bottom inset (at most 80 px); the controls, hints, banner and the camera's reserve follow. 0 in a browser. Needs a phone with a gesture bar. |
| U6 | Intro banner over the console | Fixed earlier in P0 (and follows the inset now). |
| U7 | Tagged card on short phones | **Checked, no change needed.** Screenshots at 390x844, 360x640 and 480x640 (3:4): the whole street and your base stay above the card, the card fits. |
| U8 | Pad zone bigger than the disc | **Left for a playtest.** Changing a touch target blind is worse than leaving it. |
| U9 | No feedback when the pad changes direction | **Done.** An 8 ms tick on a phone when the thumb enters a new direction (off with the Vibration setting). Feel is a device check. |
| U10 | "Web build cannot test rooms" | **Not a code problem.** Hotspot needs Android (the web build shows a layout preview, correctly). Online rooms work in a browser as soon as a server URL is set (`kalyeah/network/server_url`, or `?server=wss://...` on the page); see `server/README.md`. The missing piece is a deployed server, which is yours. |
| - | `match_hud.gd` had grown to 518 lines | The layout code moved to `MatchHudLayout` (the HUD is 473 lines and keeps to what it shows). |

## Test note
